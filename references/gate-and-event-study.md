# 闸门与事件研究：判据类型、样本单位、升格程序

七关默认「横截面日样本 + 均值/IC 判据」。当任务是**逐事件触发的闸门**（公告风险提示、事故预警、
黑名单拦截）时，这两个默认都不成立，直接套会把有效的东西判死、或反过来造出假信号。

## 1. 先判：这个工具是「提均值」还是「降尾部」

| 类型 | 典型形态 | 判据 | 用错会怎样 |
|---|---|---|---|
| 提均值 | 选股排序、择时、打分 | 七关：IC、分级价差、t | 正常 |
| 降尾部 | 过夜风险提示、事故闸门、黑名单 | **条件尾概率比** R | 均值判据几乎必然判死 |

尾部型的判据：

```
R = P(坏结果 | 事件) / P(坏结果 | 对照)
```

- 三件套写死在口径卡：`R ≥ 2.0` + 聚簇 bootstrap 95% 区间下限 `≥ 1.3` + 事件数 `≥ 150`
- 尾阈值先给经济含义再给数字：「一次 −10% 等于开盘跳空绕过止损，一次吃掉两周利润」
- 均值一并报，但**只在均值与尾部方向一致时才允许升级用途**；均值符号在样本外不复制的，只能做 WARN

实测对照（同一批事件，短持有期口径）：按均值看，处理组与对照组的差为负且过不了多重检验门槛，
按尾部看，处理组出现大幅下跌的概率是对照组的三倍上下——**按均值判死，按尾部判活。均值判据审判不了尾部工具。**

## 2. 事件型样本：单位、簇、去重

- **单位是事件，不是交易日**。L0 的「几百个横截面日」在事件研究里换成「几百个事件」，并明写单位
- 事件**成簇**：同一标的多次、同日多类。必须报两个 t：普通 t 与**簇稳健 t**（以标的聚簇：先算每标的均值，再对标的均值算 t）。两者结论不一致时以簇稳健为准——实测有一条从 t −2.44 掉到 −1.13，直接由「接近显著」变「不可信」
- **同类事件设冷却期**（如 20 个交易日）再去重，否则「决定书 → 整改报告 → 进展公告」被数成 3 个独立事件
- 双向误判要一起挡：派生公告（标题含 `整改`/`回复`）与否定式标题（含 `未被`/`不存在`/`承诺不`）都不算事件
- 区间用**聚簇 bootstrap 且配对**：同一批标的（有放回重抽）同时提供事件样本与对照样本，不要用二项区间

## 3. 主检验唯一 + 次检验升格四步

口径卡必须写死「主检验 = 哪个类别 × 哪个时点」。主检验不过即判死，其余显著结果只登记为**候选**。

次检验要升格，走这四步（**不是**换个类别重算同一批数据）：

1. 当轮不作数，判死照判
2. 下一轮**换样本**：零重叠的标的/时段，报告里校验交集为空
3. 判据与阈值**一个字不改**
4. 通过 → 记为 **L2（尾部型）**；不通过 → 整条线结束

> 注意：L0–L5 是按**收益型**信号标的定级的（L2 = 多期同向为负，可反向使用）。尾部型闸门不是收益信号，
> 它的用途上限是 WARN / 影子记录，**不得上钱、不得进排序**。所以抬到 L2 只表示「这个尾部效应是真的」，
> 不表示「可以拿它赚钱」。（v2.10 前的写法直接写「升 L2」，会与 workflow §五 的 L2 定义打架。）

升格的理由只能是「在没见过的数据上同样成立」。再加一道同族混杂的匹配检验（如按波动率档匹配对照），
过得了才算排除「这只是一群高波动标的」这类替代解释。

实测：样本内读数 → 换零重叠样本后读数 → 波动匹配后再读一次，三次数值都还在线上，才算立住。单次读数不作数。

## 4. 外部数据的可得性闸门

七关默认你能回放历史，但外部数据源会以三种不报错的方式毁掉样本：

- **覆盖率不是 100% 却看不出来**：报告的必须项是「有数据的标的/计划标的」，失败计数写进报告
- **时间戳精度不足**：只有日期的公告，按次日 00:00 生效——**只许往「更晚知道」取整，永不允许提前**。
  这条比「不用未来信息」更具体，后者管不到「日期 vs 时刻」这种半信息
- **基准序列窗口不够**：产品缓存常常只存最近几个月，拿它配几年的事件研究会静默丢掉大部分事件（实测一次 73 个只剩 6 个，且不报错）。跑之前先校验基准覆盖样本窗口
- 抓取端：分页要拿总数与实际条数对账；缺关键字段的记录要有回落字段并打标记（`clock` vs `date`）
- **先做文种/字段门，再抽正式样本。** 用固定 30+30（或同等小样本）证明查询返回的是目标文种/字段，门不过先停、改查询；门样本与正式样本分开，失败件不替换。直接按关键词抽 100 条，常见结果是抽到另一个文种，后面所有解析都白做。
- **预注册指标是目标指标；关键词命中率、下载成功率、可读文本率是代理指标。** 代理指标只能单独报，**NEVER** 用它判目标门通过或失败（“52% 有前后对照”不等于“52% 正确解析”）。报告分三层：代理命中 / 人工核对 / 目标判据；人工样本若是系统抽样而非随机，不得外推为总体率。
- **可行性试点里「未证明」≠「证明不可行」。** 停止线未过只说明当前证据不足以进入下一阶段；不得写成“该机制不存在”“alpha 为零”“全部历史都不可用”。反过来，代理指标好看也不得写成“已通过”。把缺的是哪一条证据、下一步用哪条路径补，写清楚再停。

## 5. 闸门型工具（BLOCK / WARN / CLEAR）的约定

- 三态之外必须有 **UNKNOWN**：取不到数据 ≠ 无异常，这条直接落 M3
- 均值不成立时只许出 WARN，不许出 BLOCK；交付写清「这是风险提示，不是买卖信号」
- M1 数法（决策型 ≤4 的那一路）：闸门型按「用户拿到后还要自己做的判断步数」数，
  只给事实不给动作的卡片按 ≤2 记，并写明剩余步数由谁完成（**某项目标定值，勿外推**；换域先量基线）

## 6. 多类别结果与「同一指标只有一个数」不冲突的写法

事件研究天然有 N 类 × M 时点的数，不是同一指标的 N 种算法。写法固定两层：

- **主检验**：唯一，1 个数定生死
- **旁证**：其余全部标注「旁证，不参与判定」，同行列出

先说层级再给表，否则会被读成「六个数里挑好看的」。

## 7. 判活之后怎么落地：影子记录四件套

**判活 ≠ 接线。** 尾部型结论只够资格做提示，落地形态是**影子记录**（只写台账、不执行），
产品一行不改；接线属于改产品，要用户明确要求，且先并行记录 N 期。

四件套缺一件就不叫影子模式，叫半个功能：

1. **自动触发**：跟产品的扫描产出走（找它当天最新那份候选池）。产品当天没跑 → 静默退出，
   不写记录、不补历史池——补跑会制造出「当天本来没有的判定」
2. **静默通知**：只在触发时发消息，无触发不发；反过来，**抓取失败必须发**，否则就成了 M3 的静默失败
3. **结果回填**：每条判定补 T+h 已实现结果；未到期标「待定」，**不得当成没触发**，也不填 0
4. **复盘三数**：出现次数 / 命中 / 误杀，对照用**同池内的非触发组**，不用全市场（理由见
   `quant-strategy-backtest` 的 Pitfalls：部署人群的基准率可能高一个量级）

判定去留的线要**写死在跑之前**（例：误杀 ≥ 命中两倍即停），否则攒够数据后又开始找理由。

**n=1 不构成任何信号。** 首条触发就是误杀，既不能证明工具无效，也不能证明有效；
先攒 10–20 条触发再判，中间的每一次都只当记录。

> 10–20 条是**去留复审**的样本量，不是统计结论的样本量：此时不得报 R、不得报区间、不得对外引用，
> 因为 §1 的三件套要求事件数 ≥150。两条门槛管的是两件事，别拿小的那条冒充大的。
