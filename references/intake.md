# 开工三问 · 与两条常驻规矩

> 这不是方法，是**前置判官**。方法回答「怎么做得干净」，这一页回答「这件事该不该做、做成什么样才算完」。
> 接到任何任务，先过三问；任何交付，先过第五节两查。

## 一、三问（30 秒内说完，不许跳过）

### 问 1 · 对方要的是「功能」还是「可核验的结论」？

如果交付物不能被追问「这个数从哪来、怎么重算、错了会怎样」，那它不是结论，是演示。

**判别动作**：把交付物给对方之前，先自己问一遍那三个问题。答不上来就还没做完。

### 问 2 · 这一步是在建结构，还是在填内容？

结构 = 规则、口径、闸门、审计链、DAG——能重复使用、能被别人接手。
内容 = 这一次的具体产出。

**判别动作**：这条内容能不能被一条规则取代？能，就先写规则。

先填内容再补结构，结果通常是补不上——因为内容的形状已经决定了结构长什么样，那时候你只是在给它写说明书。

### 问 3 · 钱成本和**时间**成本分开了吗？

花几十块可以随便试；花三个晚上不行。时间是最贵的资源，比调用成本贵得多。

**判别动作**：任何「要不要做」的判断，先给一个 5 分钟可行性结论，再决定要不要投几小时。

**任一问回答不上来 → 停下来问，不要用「先做起来」糊过去。**

---

## 二、常驻规矩 1 · 开工先查时间

开工前必须确认三件事，并说明「这是截至 YYYY-MM-DD HH:MM 的状态」：

1. 项目版本号
2. 最新产物时间
3. 代码库 HEAD

**不许用记忆里的状态当现状。** 工具：

```bash
python scripts/check_freshness.py <项目目录>
```

理由很实际：同一份文件可能在一小时前被另一个会话改过。按旧快照动手，等于覆盖别人的改动，而且事后看不出来。

## 三、常驻规矩 2 · 做完必须留记录

三处同时写，缺一处就等于没做：

1. **一份可引用报告**（过 `doctrine_check`），落在项目 `docs/`
2. **全局索引**追加一行：原话 / 我做了什么 / 产物绝对路径 / 下次第一步
3. **当日日志**：日期时间取自当场 `date` 的输出

主语不许省：写「我改了 X」，不写「已修复」。

---

## 四、动手前的两查（与三问不同，这是针对「已经决定要做」的情形）

1. **这条改动是净减法吗？** 新增的条款 / 字段 / 分支，顶替掉了哪个旧的同义件？
2. **跑得起来吗？** 有没有一条命令能在干净环境里验证它？没有就先写那条命令。

---

## 五、交付前的两查

1. **数字对得上吗？** 同一指标全文只有一个数；每个数都有重算命令；没跑过的标「未验证」。
2. **边界写了吗？** 最后一节是「没覆盖什么」，并且它真的在最后一节。

两条都过，才允许说「完成」。
