# 合成示例：一次完整走查（synthetic: true）

> **本文件里的每个数字都是编的。** 它的用途只有一个：让读者看到一条完整的路——
> 口径 → 数字表 → 判级 → 可信度 → 重算 → 可引用 → 边界——长什么样。
> 包里所有实测内容已删除，这份示例是为了让流程仍然可被执行而重造的。
> 它应当被判定为「不可引用」；如果它被判成「可引用」，说明包自己的检查器坏了。

假设的任务：一个工单分诊工具，输出「今天先处理哪 10 张」。十个人的小团队用，用错不会掉钱，
但会让人做完不该先做的事。强度档 = 标准。

---

## 一、数据口径

| 项 | 定死的内容 |
|---|---|
| 主指标 | Top-10 命中率 = 前 10 张里被人工确认为「该优先」的比例 |
| 主检验 | 20 期 × 每期 50 张 = 1000 张工单；同一批工单、同一时段，只换排序算法 |
| 基线 | 人工排序的 Top-10 命中率 = 38.0% |
| 波动 | 期与期之间的基线波动 σ = 8.0pp |
| 阈值程序 | N = 20 → MDE = 2.8 × 8.0 / √20 = 5.01pp；经济底线 = 5pp；取较大者 → **阈值 5.0pp** |
| 唯一引用源 | 本表。全文出现的 6.4 / 5.1 / 7.7 / 4.2 / 3.58 都以此表为准 |

## 二、数字表

| 样本 | 命中率（改造后 vs 基线） | 效应（pp） | t | 过 5.0pp 阈值 |
|---|---|---|---|---|
| 全 20 期 | 44.4% vs 38.0% | +6.4 | 3.58 | 是 |
| 前 10 期 | 43.1% vs 38.0% | +5.1 | 2.02 | 是 |
| 后 10 期 | 45.7% vs 38.0% | +7.7 | 3.05 | 是 |
| 剔除贡献最大的 2 期 | 42.2% vs 38.0% | +4.2 | 2.38 | **否** |

前 10 期与后 10 期的效应平均 = (5.1 + 7.7) / 2 = 6.4pp，与全样本一致。

## 三、判级理由

全样本 +6.4（单位 pp，下同）、t = 3.58，过统计门槛，也过 5.0 的经济底线，看起来可以判 L4。
但第 6 关（集中度）把它拉回来：剔除贡献最大的 2 期之后，效应只剩 +4.2，低于阈值 5.0。

也就是说，这 6.4 里有 2.2 来自 10% 的样本。剩下的 90% 单独看不足以支撑改造。

按 `workflow.md` 的分级表，这不是「统计显著但价差小于成本」（L3），而是
**效应集中在少数样本、去掉后不成立**——判 **L1：停手，别调参**。

判死的是「这个排序算法在常规周里优于人工」这条主张。判死的不是这个工具本身：
工具的判据、留痕、敢说「今天没有该优先的」这三件事仍然成立，可以照做。

## 四、可信度

- **synthetic: true** —— 全部数字为合成值，不可引用、不可当阈值抄。
- 这份文档能证明的只有一件事：这条流程走得通，检查器能跑。
- 它证明了该方法可用，却没有证明该方法有效——这两件事必须分开记。

## 五、重算命令

```bash
# 阈值（MDE 近似，双侧 5%、约 80% 功效）
python -c "import math; print(round(2.8*8.0/math.sqrt(20), 2))"   # → 5.01

# t 值
python -c "import math; print(round(6.4/(8.0/math.sqrt(20)), 2))" # → 3.58

# 本包自检
python scripts/doctrine_check.py examples/synthetic-walkthrough.md --explain
```

## 六、可引用的三条事实

1. 阈值不是拍的：由 σ、N 与经济底线三者算出来，过程写在口径表里。
2. 判级要回答的是「去掉最强的那部分样本还成不成立」，不是「p 值够不够小」。
3. 判死一条主张，不等于判死整个项目——要写清死的是哪一句。

## 七、未覆盖边界

- **没做**样本外：20 期全部用于估计，没有留出期。
- **没做**组合层：这是单点命中率，没算人工复核成本变化。
- **没发现**不等于「不存在」：本示例没有检验「小团队在忙季是否更好」这类条件效应。
- 数据结构：只有 1000 张工单、单一时段、无跨团队对比——样本量小到只能看方向。
- 未做微动作审计（M1–M5）：本示例只演示结论形态，不演示人机接口闸门。
