# 工作流详表（双入口 · 六阶段 · 两套验收）

## 一、双入口

| | 入口 A · 新建 | 入口 B · 存量审计 |
|---|---|---|
| 起点 | 什么都没有 | 已有能跑的东西（有用户/有结论/在产出） |
| 首步 | P1 规划分工 | **P3 否决器**（先造能杀死它的东西，不碰产品） |
| 首产出 | 分工表 + 范围边界 | 一个等级 L0–L5 + 被排除的解释 |
| 分叉 | P1→P6 顺序走 | 判死 → 停手 / 判活 → 转 P5 再用 P6 改造 |
| 终止 | 两套验收标准全过 | 能对「继续还是止损」给出一个字，且列出排除了解释 |

入口 B 的顺序不可倒。倒过来先改产品，沉没成本先长出来，之后每次检验都会不自觉找理由让它活下来。

## 二、六阶段

| 阶段 | 关键动作 | 产出 | 通过线 |
|---|---|---|---|
| **P1 规划分工** | 拆任务、定谁做、定什么不做、定什么情况停 | 分工表 + 范围边界 | 每个任务有唯一负责人和唯一验收人 |
| **P2 确定唯一口径** | 把每个会出现的数字钉死一个算法 | 口径卡 | 签字后不得再改；改一次 = 重新开工 |
| **P3 否决器 + 初步验收** | 按强度档造反否器；同步定「机器可判」的通过线 | 否决报告 + 初步验收清单 | 能给 L0–L5 且列出被排除的解释；每条标准可自动判真假 |
| **P4 构建 demo** | 只做能产生判断的最小闭环 | 可运行原型 | 干净机器上跑通一次 |
| **P5 微动作 + 需求分析** | 人的路径压测 + 回头核需求 | 微动作表 + 缺陷清单 + **最终验收标准** | M1–M5 达线（适用范围内）；每条缺陷可复现可排序 |
| **P6 最终构建** | 按最终标准改造、打包、交付 | 成品 + 边界说明 + 交付状态卡 | 两套标准全过，或按三档交付 |

## 三、验收定两次（最容易被合并，也最不能合）

| | 初步验收（P3） | 最终验收（P5） |
|---|---|---|
| 何时定 | 动手之前 | 见过真实使用之后 |
| 判什么 | 机器能判：t 值、耗时、通过率、错误码 | 人能判：推断步数、歧义数、静默失败数 |
| 防什么 | 自己糊弄自己（「看着差不多」） | 交付一个测试全绿但没人会用的东西 |
| 改不改 | 只许变严，不许放宽 | P5 新增，不回写 P3 |

合并后果：只定初步 → 指标达标但没人会用；只定最终 → 标准随实现漂移，变成事后合理化。

结构性案例：一个工具初步标准全绿，P5 却发现推断步数超线且状态不一致
——按初步标准早该交付，按最终标准根本不成立。具体测量、项目身份与出处不进入公开版。

## 四、P5 的两个半边

**微动作半边**：见 `micro-action-audit.md`。审的是判断责任落在谁身上，不是界面好不好看。

**需求半边**——三个问题，每个都用他的**真实动作**答，不用假设：

1. 他真正要完成的任务是什么（不是我们实现的功能）
2. 他目前拿什么替代（Excel？纸笔？另一个工具？）知道替代品才知道竞品是谁
3. 我们的输出在他那一步被怎么用（直接下单？还是先抄到别处再算？**要抄就是没做完**）

第 3 问答案是「他得先抄出去」→ 这个交付不管指标多好，都还没完成。

## 五、分级用语（只许这些）

| 级别 | 条件 | 可以怎么用 |
|---|---|---|
| L0 | 样本 < 几百个横截面日、单一 regime、缺成本/成交假设 | 只能当假设，不得对外 |
| L1 | 未通过统计门槛，或分段全在 0 附近 | 停手，别调参 |
| L2 | 多期多段同向为负且经济量级显著 | 可反向使用（若标的允许），否则弃 |
| L3 | 统计显著但价差 < 成本，或容量不可接受 | 只能做负面筛选 |
| L4 | 七关全过、未做样本外 | 可继续研究，**不得上钱**（七关清单只在 `veto-gates.md` 有一份） |
| L5 | 样本外同向且量级可接受 | 仍受成交与容量约束，可小仓验证 |

**事件型样本的换算**：单位是事件而不是横截面日时，「几百」按**事件数**算，并同时报簇稳健 t；
事件高度成簇（同标的反复触发）时，独立单位数按**标的数**算，不按事件数算——否则 t 值会虚高一个量级。

## 六、交付状态卡

闸门写「任一不达线 = 不通过」，但现实常要交付。**允许带风险交付，不允许静默交付。**

状态卡骨架（含 `<!-- gates: ... -->` 机器可读行）只在 `templates.md` §五有一份；三档的条件与必写项只在 `SKILL.md` 的交付三档表。本节不再复制，复制即两处漂移。

## 七、成本判据（否决器值不值得建）

公式与三档判据只在 `SKILL.md` 第 0 步问 2 有一份。

按第一条硬闸门的标准，「否决器太贵以至于不值得建」本身就是一条合法失败判据——写下来，它就不是偷懒。

## 八、没有可回放历史时（七关的前置条件）

七关默认你能回放历史，这是它最贵的隐含前提。新产品、新流程、没跑过的业务，别硬套，走三条之一：

| 路径 | 做法 | 能得到什么 |
|---|---|---|
| **影子模式** | 照旧做决定，工具并行给建议，**只记录、不执行**，攒够 N 期再按七关回看 | 少则 4–8 期就能看出方向，不产生真实损失 |
| **反向回放** | 拿现有做法的过去 N 次判断，反查错了几次（有记录就能做，不需要工具） | 直接得到基线错率和错在哪一类 |
| **只做接口层** | 只改 M1–M5（敢说不、不静默失败），**不宣称有效性** | 可交付的产品形态；交付写「未做有效性验证」 |

三条都不选 = 这件事还不该做。**「没有历史数据」不是跳过验证的理由，是换一种验证方式的理由。**

## 九、阈值怎么标定（不给刻度，只给程序）

每道关的通过线按五步定，写进口径卡；写不出来说明这关还没做：

1. **先量基线**：不做任何改动，同一指标在 N 期上量一遍，记均值与波动 σ。
2. **算最小可检测效应**：`MDE ≈ 2.8 × σ / √N`（双侧 5%、约 80% 功效的近似；前提是各期近似独立、波动稳定，期与期高度相关时先换算成独立单位数）。
3. **算经济底线**：这件事值得动手的最小改善是多少（省多少工时 / 少多少返工 / 多少钱 / 多少误判）。
4. **阈值取两者较大者**，并在口径卡上写全 N、σ、MDE、经济底线、最终阈值、谁签字。
5. **N 不够时**：拉长窗口、合并同质样本，或明写「只能看方向、不能看数值」并判 L0。

**σ 只有估值时（第 2 步的缺口）**：MDE 要用 σ，但 σ 只有跑完才有。口径卡先写「σ 估值 X（写明来源：经验或同类项目）」，
跑完用实测 σ 覆盖一次，报告留痕「估值 → 实测」；两者差 >20% 时按**较严一侧**重算 MDE 与阈值，且只许变严。
不写这条路，实操只剩两个出口：卡住不开工，或事后偷偷改阈值——后者正是本教义最恨的。

合成示例（数字是编的，只看算式）：20 期、σ=8pp → MDE ≈ 2.8×8/√20 ≈ 5.0pp；经济底线 5pp → 阈值定 5pp。若只攒到 5 期，MDE ≈ 10pp——这时「看到 8pp 提升」什么也说明不了，只能判 L0。
