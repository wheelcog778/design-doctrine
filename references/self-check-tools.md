# 审自己的检查器：判定口径、同构返回、回归集

触发：要写或改一个「跑一份文档/一个包，判它够不够格」的检查器——文档七件套、交付状态卡闸门、
跨文件重复行、泄漏扫描、版本同源。也用于自查：手上这个工具判得对不对。

一句话主张：**检查器只能按结构判，不能按「关键词在全文出现过」判。** 否则它会放过最该抓的那类文档，
而且作者还能用一句话把失败解释掉。

## 1 判定口径先写死

| 问法 | 结果 | 为什么不行 |
|---|---|---|
| 全文有没有出现「口径」两个字 | 假通过 | 注释、举例、否定句里都会出现；流程卡靠散词就能混过 |
| 有没有一节标题讲口径，且该节正文有实质内容 | 可用 | 这是结构判定：位置 + 内容 |
| 表格/命令行按类型找（不限位置） | 可用 | 它们本身就是证据形态，不依赖标题 |

口径写成两句话再动手：**必需项在标题对得上的那一节里才算通过；证据型检查（数字表、可执行命令）按形态找。**

## 2 结构化四步

1. **剔代码块**：同时识别 ``` 与 `~~~` 围栏，并记录围栏字符与长度；闭合只认同字符、足够长的标记，
   围栏内另一种标记只是正文。把整块替换成空行（保留行号）。理由：命令、示例表格和机器状态行常藏在代码块里，
   漏剥一种围栏或误判闭合都会让示例冒充正文证据。
2. **切节**：按 `#{1,6}` 标题切，保留首个「标题前正文」。
3. **定位节**：标题含该项关键词；**必需 prose 必须先剥代码再判非空**，空围栏不算实质内容。
   表格与命令另按证据形态检查，不能用 prose 的非空规则替代。
4. **撞词要继续往下找**：命中关键词的节可能不是要的那节（`数字表（不是结论，是数字）` 会撞上「结论」）。
   所以是「对每个候选节依次试」，不是「第一个同词标题就停」。不同检查项的关键词还要去掉交叉，
   防止「可引用」节同时冒充「可信度」节。停早或关键词重叠都会让结构判定失真。

## 3 返回结构与崩溃面

**结论不是一个布尔。** 至少要四态：通过 / 带风险交付 / 不通过 / 无法判定。把它们压进一个
`verdict` 布尔，会立刻长出两种病：脚本说「通过」而正文说「只能带风险交付」（自相矛盾），
或者「无法判定」被当 0 处理（默认放行）。退出码同步：0 只给通过，1 给不通过，3 给带风险交付，2 给无法判定。

- **所有分支返回同一套键**。提前 return 的分支少一个键（典型：`notes`），渲染函数一取就 `KeyError`——
  而这恰好发生在「输入不完整」这条关键路径上：用户第一次拿一份没写状态卡的文档来跑就崩。
- **渲染函数不假设键存在**，或用 `dict.get`，或在构造函数里统一建骨架再填。
- **退出码要有语义**：0 = 可引用/通过；1 = 不通过；2 = 用法错误或「无法判定」；3 = 带风险交付。
  「无法判定」必须是 2，不能混进 0（等于默认通过）也不能混进 1（读者会以为结论是否定的）。
  带风险交付必须是 3：它和「不通过」都不该是绿，但自动化要能分清「可交、残留需签字」与「不许交」。
- **机器可读标记要先剔「引用」再取「正文」**：`<!-- gates: ... -->` 这类行在正文里常常只是在解释格式（行内反引号里、代码块里、或带省略号）。先剔代码块与行内代码，再要求键齐全（五个都在）；键不齐 → 「无法判定」（那是引用示例），**不是**「不通过」。否则一份只是讲格式的文档会得到一个看起来很像结论的错误结论，比崩掉更难发现。
- **正文写 MUST 的字段，解析器也必须必填**：不能正则里可选、文档里强制； happy-path fixture 必须带齐全部必填字段，
  另配一个缺字段用例判「无法判定」。否则错误测试预言会把缺字段状态卡固定成「通过」。
- **引号不是禁用语豁免符**：只在明确的讨论/否定句里剔除被引用的禁用语，正式结论加引号仍要命中。
  全局删引号会把最该拦截的模糊结论静默放行。

## 4 回归集（新加一条判定就配一条）

自测必须覆盖下列类别，缺哪类就有一类缺陷能静默上线：

| 用例 | 期望 |
|---|---|
| 完整样本 | 通过 |
| 残缺样本 | 不通过，且缺项数等于预期（数字写死，不写「若干」） |
| 禁用语命中 | 不通过并列出命中的词 |
| 假阳性回归：内容只在代码块里 | 判缺项（防子串/防 fenced 误判） |
| 假阴性回归：标题撞词 | 仍能找到正确那一节 |
| 引用回归：状态卡格式写在正文/行内反引号/代码块/带省略号 | 判「无法判定」，不是「不通过」 |
| 空输入 / 缺关键行 / 畸形行 | 不崩，给「无法判定」 |
| **假阳性：证据在别的节**（全文任意位置有带数字的表即通过） | 判缺项——证据型检查也要定节 |
| **假阳性：机器行夹带文字**（`<!-- gates: 备注 M1=4 … 结束 -->`） | 判「无法判定」，不是通过 |
| **语义：计数来源是单人**（`M1_src=solo`） | 最高「带风险交付」，不得「验收通过」 |
| **语义：文档是合成示例**（`synthetic: true`） | 不得判「可引用」，最高「仅结构完整」 |
| **围栏变体**：`~~~`、空围栏、围栏内另一种标记 | 示例不得冒充证据；空 prose 判缺项；章节解析状态不被打断 |
| **禁用语变体**：讨论句里的引用 vs 结论里的引号 | 前者不误报，后者仍命中 |
| **必填来源缺失**（如 `M1_src`） | 判「无法判定」；通过 fixture 本身必须含该字段 |
| **必需顺序**（如未覆盖边界必须末节） | 边界后追加章节即不通过 |
| **元数据落点**（如正文 `version:` 冒充 frontmatter） | 不通过；只认声明过的结构位置 |
| **排除集与外部状态**：事实只在历史快照、Git 不可读、显式索引路径不存在 | MISS/无法读取/用法错误，绝不能说 OK |

贯穿整张回归表的重点：**崩溃、假通过、把引用判成结论，这三类都不报错**，只有在对抗用例里才会显形。

## 4.5 数重复的脚本：命中时要看得出为什么

`--fact` 传术语（动作名、状态名、表头）会误报：定义一处、指针一处，脚本报 DUP，人手上一脸问号。
规则：命中 >1 时打印**每个文件里那一行的原文**并标「指针?／定义?」（含「只在…有一份」「见 references/」「不复制」的多半是指针），
让使用者当场分流；用法说明里写清 `--fact` 只传事实层串（阈值、指标口径、独有数字），术语本来就该在多个文件出现。

**事实扫描与重复扫描必须使用同一个当前文件集**：已排除的历史快照不能再被 `--fact` 加回来；
事实只剩快照、当前正文已丢失时必须 MISS。版本号等结构化元数据要锚定声明的位置（如 YAML frontmatter），
不能在全文取第一个同名字段。外部命令必须检查返回码并把「存在但不可读」与「不存在」分开；
显式传入的索引路径不存在要 fail-closed，不能因跳过可选分支而整体 OK。

## 4.6 新增判定规则先量误报率

加一条自动检查之前，先在**包内现有合规文档**上跑一遍量误报。误报超过约 10% 的规则不准合入：
检查器的价值建立在零误报上，用户踩三次误报就会整体关掉它，之后连真阳性也一起丢。

典型反例：「正文里出现的数字必须能在数字表里找到」。字符串相等不等于数量相等——样本期、
成本区间、带 t 值的结论本来就只写在正文。实测一份真实案例文档，22 个正文百分数里有 10 个
不在任何表格中出现（45%），且全是合法表述。要查数对不对，只能人查或按口径重算，不能靠正则。

**同类：跨文件「同名指标异值」检查。** 比对前必须做数值归一——`7` / `7.0` / `+7` 视为同值，
`%` 与 `pp` 分开比；否则纯格式差异就会报冲突，误报照样让人关掉检查器。

**符号是这条规则的例外，而且方向与直觉相反：想抓方向错误，恰恰不能把符号放进比较键。**
实测：符号一进键，包内合规文档当场判死——正文「每笔少赚 X%」对表格「−X%/笔」说的是同一件事，
量级相同、方向由动词承担。中文里「少赚 X」「回落 X」这种写法极常见，按符号判等于把合法表述全打成错。
正确分工：**判死用「数值 + 单位」**（符号归一到绝对值，避免误杀）；**符号不一致只作提示**——同一个量级
在别处只以相反符号出现时打印一行，不改 verdict。要让符号翻转直接判死，得先证明包内不存在「少赚 X%」
这类句式，一般证不出来。符号翻转属「写错了」，本来就不在启发式检查器的射程内：检查器防的是「忘了写」。

## 4.7 三条机检（2.20.0 并入）

三条检查只在「写漏了」层面有效，不要拿它代替人查数：

1. **数字对账**（`doctrine_check.py`，默认开）
   - 只查 `3 判级理由` 节里出现的带符号小数/百分比，是否在口径节或数字表中出现过；整数与常见阈值（`1.96`、`0.05` 等，见 `COMMON_THRESHOLDS`）跳过。
   - 单位参与比对：`1.23` 与 `1.23%` 不是同一个数；符号不参与（`−0.532%` 与 `0.532%` 视为同量级），因为中文「少赚 X%」与表格「−X%」是同一件事。
   - 局限：它只防「判级理由里凭空出现一个数」，不证明这个数算对了；要证算对，仍须回源文件重算。

2. **脚本核验**（`doctrine_check.py --root <项目目录>`）
   - 扫 `6 重算命令` 里 `python`/`python3`/`bash`/`sh` 后跟的相对路径 `.py`/`.sh`，在 `--root` 下必须真实存在；绝对路径跳过，找不到即判「不可引用」。
   - 局限：只认这四种解释器与这两种后缀；`Rscript`、`node`、`sqlite3` 等命令不在此列，仍需人工核。

3. **指标冲突**（`doc_dup_scan.py --metric <指标名>`，可重复）
   - 跨文件扫 `指标=数值` / `指标: 数值` 形态；比对前归一：`7` / `7.0` / `+7` 同值，`%` 与 `pp` 分开；符号保留（负值与前值是两个数）。
   - 输出 `[CONFLICT]` 即退出 1；`[NONE]` 说明没命中该形态，不等于该指标只有一处。
   - 局限：只认单行 `指标=数值`；表格里分散的数字、正文叙述里的数字不在射程内。

命令：

```bash
python scripts/doctrine_check.py 报告.md --root .
python scripts/doc_dup_scan.py . --metric M1_before --metric IC
python scripts/doc_dup_scan.py --selftest
```

## 5 自证禁令（最容易犯的一条）

检查器对某类文档判「不通过」时，**不许在 README 里补一句「那是设计如此，不是缺陷」**。
那句话把验证责任从工具收回作者手里——一份专门要求「不许事后给自己编解释」的包，自己先编一个，
整包的立论就塌了。

正确做法是让工具对任何文档同判，然后复述它的结论：

> `python scripts/x.py SKILL.md` 的结论是「不可引用」。这是正确答案：流程卡没有口径卡、没有判级理由、
> 没有重算命令，按定义就不是结论文档。工具对所有文档用同一把尺子，这条结论里没有例外条款。

区别在于：前者是**豁免**（本该失败的东西被放过），后者是**结论**（它本来就该失败）。

## 6 拿包自查的顺序

0. **示例与模板也要跑**：包里的 end-to-end 示例用它自己的规则跑一遍，跑不过就是包没通过自己的验收。
   示例若来自单人走查或为合成数据，必须在文首写成机器可读标记（`M1_src=solo` / `synthetic: true`），
   让检查器自动降级——靠正文一句「此例为合成」不算，脚本不会读那句话。

1. 把包内所有 `.md` 都跑一遍 `--doc` / `--gates`，看**哪些意外通过**——意外通过比意外不通过危险得多。
   同时用独立构造的对抗输入复现旧行为并核对退出码；包内 selftest 全绿只证明已有预言没坏，不证明覆盖足够。
   **改判定规则时，还必须拿旧版与新版检查器对同一批文档各判一次、逐文件 diff `verdict`**：
   任何变化都要能解释成「本来就该变」，解释不了就是回归——最常见的回归是合法用法被新规则误杀。
   看变化清单，不看通过率：通过率从 92% 掉到 88% 可能只有两篇文档、其中一篇就是参考案例。
2. 对每个「意外通过」找原因：是节标题撞词、是代码块里的内容、还是关键词太泛。改判定，不改文档；
   定向用例先红后绿，再并入 selftest。
3. 改完再跑一遍，把「流程卡判不可引用、结论文档判可引用、状态卡判通过」这三条写进交付记录当基准。
   最终还要拿一份真实结论文档跑生成物检查，避免自测 fixture 没覆盖实际排版与围栏组合。
4. 检查器自身的版本要跟着判定口径变：口径改了而版本没改，下一个人分不清两个数哪个对。
