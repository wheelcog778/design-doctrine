# 决策型工具的设计教义 · v2.20.2

> 先造出能杀死这个想法的东西，再造这个想法。

一套流程卡 + 四个能跑起来的检查脚本，只干一件事：**建造或审计「有人要拿它做决定」的工具**（买 / 选 / 排 / 标 / 批）。

这不是教程，是一张要照着执行的清单。四个脚本零依赖，真发现问题时**四个都返回非零**。

- 纯 Python 标准库（3.9+），零依赖
- 既可以当 agent 技能用（`SKILL.md`），也可以当一张 A4 流程卡用
- 每一道闸门都是一个数，不是形容词

---

## 唯一主张

> **你不能复算的结论，不是结论。**

包里其余东西都是为这句话服务的：写第一行代码前先写失败判据；一个指标只能有一个算法；验收定两次（机器一次、看过真实使用之后的人一次）；任何报告的最后一节永远是「**没覆盖什么**」。

## 快速上手

```bash
python scripts/doctrine_check.py examples/synthetic-walkthrough.md   # 必须被判「不可引用」
python scripts/doctrine_check.py <你的结论>.md --explain             # 退出码 0 = 可引用
python scripts/doctrine_check.py <你的状态卡>.md --gates
python scripts/doc_dup_scan.py . --metric M1   # 同名指标跨文件异值
python scripts/version_lint.py                 # 版本单一性
```

当技能用：把整个目录放进任意 skills 分类目录，`SKILL.md` 里的路由表会决定某类任务该读哪几份。
当流程卡用：只读 `SKILL.md`，路由表指向 `references/` 时再打开。

## 这份东西不能做什么

- **不能判断你的结论对不对。**它只拦「结论变得不可信」的那几种便宜方式：没有失败判据、一个数两个算法、报告从不写漏了什么。
- **不提供阈值。**`veto-gates.md` 里每一关都写「在你自己的域里标定」，然后给出标定程序（`workflow.md` §9）。凡是随包附送通用刻度的，都是在教你抄别人的噪声底。
- **不宣称方法在任何领域有效。**脚本经过测试，规则仍是假设。

**标定状态，明说**：公开版不提供领域标定或实测证据。L0–L5 的分级与 M1 的通过线都必须在你的领域重标。
示例里的候选、容量、成本等词只是演示，不提供内部项目的身份线索。保留闸门结构，
所有阈值从头重标——本包不给现成刻度。

## 证据等级：假设级（L0–L1）

本公开版**派生自内部版**。让内部版强于「一个观点」的东西，这里全删了：实测数字、项目身份、案例、运行日志。

删了什么、代价是什么：

| 删除项 | 为什么必须删 | 代价 |
|---|---|---|
| 带实测数字的案例 | 样本量与区间算术是最精确的指纹 | 无法再展示「这条规则让一个真花了钱的项目被叫停」 |
| 全部实测效应与 t 值 | 读者在包内复算不了 | 十条铁律失去证据列，降为假设 |
| 内部路径、项目名、数据源 | 会识别出作者和领域 | 示例只能重建成合成的 |

**因此：这里每一条都是假设，不是发现。**可以当经验引用，不可以当结论引用。任何阈值都别照抄——这里没有阈值。想要数字，诚实的答案是「不在此仓」，而且这是故意的。

这就是这套方法在对自己执行它自己的规矩：**不要拿读者看不见的证据给方法放贷。**

## 与内部版的关系

本仓是派生的分发件，**不单独演进**，按同一版本号从内部版重出。方法的唯一真源是内部版。
两份并存不叫漂移——前提是把关系写清楚，这一节就是为此存在。
