# 同义收口：把一份越改越长的教义/文档收回单事实源

触发：同一张表或同一条规则在两处各有一份；本体只涨不跌；改了一处，另一处还留着旧阈值。
这是「同义对账」铁律的执行程序。一句话主张：**同一事实只能有一个可编辑的落点，其余位置只许是指针，且指针里不许出现数字。**

## 七步（顺序不可倒）

### 1. 先立账，再动刀：三张清单，一个都不许跳

**动手之前**必须落下三样东西，写不出来就不许改。

| 清单 | 内容 | 不写会怎样 |
|---|---|---|
| ① 现状计数 | 每条事实 grep 到的**可编辑落点**（文件:行） | 分不清"删对了"还是"删漏了" |
| ② 数字逻辑 | 要碰的每个数字：**来源**（哪条命令/哪张表）、**算术自洽**、**跨文件是否同一个**、**口径是否被当成矛盾** | 数字错一次要改三遍：正文、摘要、回复里各一遍 |
| ③ 目标值 | 改完应该剩几处、几行、哪个版本号 | 只能用"感觉"收工 |

```bash
python scripts/doc_dup_scan.py . --ignore <历史快照.md> \
       --fact "<表头串>" --fact "<状态名>"      # 重复行 + 每条事实的落点数，退出码 0=通过
```

没有脚本时用 `grep -rn "<这条事实的唯一串>" --include=*.md .` 手数。
`--fact` 只传**事实层**串（阈值、表头、独特数字）；术语和枚举值（动作名、状态名）会误报，它们本来就该在多个文件出现。

数字逻辑四项，逐条过：

- **算术**：乘积、差值、百分比、分项加总。写"样本数 × 交易日数 = 总观测"之前先乘一遍——满格与实际值之间那 5% 上下的缺口，必须说清是停牌、未上市还是缺数据，否则读者一乘就发现对不上。
- **同源**：同一个数在几个文件里有可编辑落点？只许一处，其余是指针，且**指针里不抄数字**（抄了就会过期：长文里写死"执行版 v2.2.0"，四个版本后还是 v2.2.0）。
- **口径差**：两个不同的数看着矛盾时，先判是不是口径不同（1439 个交易日 vs 1415 个可排序日）。是 → 写明差在哪；不是 → 删一个。**两个数并列不解释，等于没对账。**
- **结构计数**：标题写"六步"正文有七节、写"六阶段"却列出九项——这类错误 grep 查不出来，只能数一遍标题和列表项。

### 2. 分层：事实层 vs 索引层

- **事实层（只能一份）**：规则、阈值、口径、实测数字、例外条件。改了他处会跟着错的东西。
- **索引层（可多份）**：路由表、文件清单、"见 X"的指针。允许重复，因为它们不含事实。

判据一句话：**这句话改了他处会不会跟着错？会 → 事实层。** 分层做错，后面全错：把索引当事实删掉，读者就找不到入口了。

### 3. 判漂移：两份拷贝已经不一样时，先合并再删

逐字对比两份同一张表。差异处不是"谁更新"，而是"哪份多了条件"——多出来的那半句例外，往往是唯一的真信息，
少的那个版本就是错的。合并方向：取更全/更严那份做基线，逐条对齐后再删掉重复的那份（与 workspace-curation 铁律 7 同一逻辑）。

### 4. 留一份，其余改成指针

指针只写"去哪读"，一个数字都不抄：

```markdown
> `[这条事实]` 只在 `[唯一文件]` 有一份，本文件不复制（复制即两处漂移）。
```

模板文件里的"空骨架"也算一份拷贝：能压成一行（`M1 推断步数=__ · M2 无结论=__`）就别留一整张表。

### 5. 重复分两种，别一刀切

- **真重复**（同一句话、同一组数字）→ 删或改指针。
- **双层结构**（规则 + 执行清单）→ 两层都留，但措辞必须不同：规则写"必须"，清单写"这次做了吗"。
  同一句话在两层原样出现，才是重复；换个问法去问同一件事，是索引。

删之前问一句：删了以后读者还能找到入口吗？找不到 → 改成指针，不要删。

### 6. 修漂移副产品

同一批文件里的小病一起修，它们都是"两处各自演化"的症状：

- 重复编号（同一份文件里两个 `## 五`）。
- 标题与内容不同源（标题写"八问"，内容是七问）。
- 悬空引用（正文引"铁律 N"，本体已不列编号）→ 给编号找唯一的定义文件，或把编号删掉只留描述。

### 7. 复验 + 同源 + 归档

- **复验**：把第 1 步那三条命令原样再跑一遍，对照目标值。改写里出现的每个数字（"旧行数→新行数"）都取磁盘实测，不是内存里的变量。
- **同源**：skill 名 / README 标题 / frontmatter version / 分发包名四处一致。
- **归档**：旧 zip 移进 `_归档/<日期>/` 并记 `_moves.json`；目录里只留当前版本，否则下一个人必然拿错。
  重打包后解压验一次，别信打包命令的退出码。

## 四个坑

- **别拿渲染视图当锚点。** `skill_view` / `read_file` 返回的是 markdown 渲染结果，可能与磁盘字节不同
  （`**MUST** 停下统一` 渲染成 `**MUST 停下统一**`），照抄写的 `old_string` 精确匹配 0 命中。
  用 Python 读原始文本、按行前缀定位，或先 `print(repr(line))` 看清再改。
- **replace 要赋回，统计要看磁盘。** `t.replace(a, b)` 不会改 `t`；拿旧变量去数行数会得出"没变化"的假结论，
  然后照着结论再改一遍，改出第二处重复。写完重新读文件再数。
- **"更简单"不等于"删细节"。** 收口删的是同义，不是边界。表里多出来的那半句例外、状态卡里那行基线，
  删了就是丢信息——它们不是重复，是同义收口要保住的东西。
- **改一段先定边界：区间结束在下一个同级标题，不是文件尾。** 找起点 → 找下一个 `##`/`###` 才切区间；
  替换前后各列一次小节清单对数。开到文件尾的区间会静默吃掉末尾章节（打包、复验、行数统计都查不出来），
  等你发现时已经在不完整的东西上算过三轮数了。

## 收口后自检（五条）

- [ ] 每个事实 grep 到的可编辑落点 ≤1（模板空骨架最多 2，且不含阈值）
- [ ] 所有指针里没有具体数字
- [ ] 改写里提到的行数/条数/版本号都是实测或实测后写下的
- [ ] 版本号、README 标题、zip 名同源；旧包已归档
- [ ] 拿自己定义的检查器跑一遍改过的文件（不只跑目标文件）；新文件已进索引、路由与命令
